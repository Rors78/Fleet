## 2. What was broken, and why it mattered

Three defects in the subscriber pipeline. All three shared a signature worth
naming: **content went nowhere, or went out wrong, and nothing said so.**

### 2.1 Card footers asserted a bot count that was never measured

`card_renderer.py` printed the literal `"19 bots · live"` on every subscriber
card — both footers, all 8+ call sites, `show_bot_count` defaulting True. It
was never derived from anything. It was wrong in three ways at once: the fleet
was at 0 while it claimed 19; only 18 are pollable by construction
(`bot_responder` has no port, so `bot_registry_list()` filters it); and it
never reflected health even in normal operation.

Direct violation of "No fake stats — ever."

**Now:** `CardRenderer.set_bots_alive(n)` fed from `aggregate.bots_alive`;
`_bot_count_text()` returns `None` when unknown and the footer **omits the line
entirely** rather than asserting a number. Non-int/negative input is treated as
unknown.

### 2.2 The regime feed was a clock, not a signal

93% of a week's sends were REGIME_CHANGE, arriving at a ~61-minute cadence.
Cause: `_FLEET_DEDUP_TYPES` collapsed the dedup key to the bare event type,
so all ten regime-emitting bots shared **one** bucket, and `dedup_window_s=3600`
released exactly one card per hour — whichever bot fired first.

Compounding it, the bots hold unrelated notions of "regime" (trinity
TRENDING/RANGING per pair, nexus SYSTEMIC/MIXED, contrarian NEUTRAL/FEAR,
chronos session_overlap/high_activity), and **60.9% of all transitions were
pure A→B→A flip-flops** — trinity alone contributed 635 of its 765 events.

The code comment claimed *"Only fires when AEGIS actually flips."* No such
check existed; any bot's regime event passed.

**Now:** AEGIS only (the fleet risk authority), no-op changes (`from == to`)
suppressed, source-scoped dedup key, plus hysteresis in `AlertGate`
(`check_hysteresis`, `regime_hysteresis_window_s`, default 1800s) that swallows
a reversal of the previous transition.

Replay of **1,633 real bus events: 1,633 → 37 sends**; ≈2/day on recent data.

### 2.3 Every trade card had been silently dropped since April

`telegram_paid_chat_id` is empty. `ChannelOps.send_paid` returned `False`
immediately on an unset channel **with no log line**. Trade events reached the
bus and routed correctly (`paid=True, free=False`) — they died at the channel.

745 paid sends succeeded through 2026-04-11. Every attempt after that failed.
On **2026-07-28 alone, 156 were dropped — including all 58 TRADE_OPEN and 6
TRADE_CLOSE.** Nothing recorded it anywhere.

**Now:** the unset-channel path logs a warning and records the attempt.
`TRADE_OPEN`/`TRADE_CLOSE` route `free=True` **temporarily** so they reach
subscribers at all — free bodies already redact entry/bot behind
"🔒 Full details for subscribers", so the tier distinction survives.
`delay_free_s=0` deliberately: a 4h-delayed trade signal is worthless.

**This is marked TEMPORARY and needs an architectural decision — see §4.**

## 3. What was built

A platform-agnostic broadcast seam, in two stages, because the operator intends
to broadcast to X and other platforms.

`TierRouter`, `CardFormatter`, and `CardRenderer` were already platform-neutral;
only the send path knew about Telegram.

- **`Transport`** — protocol: `send_text(tier, …)`, `send_image(tier, …)`,
  `stats()`. `tier` stays in the interface because routing produces tier
  decisions; each transport maps tiers onto its own reality.
- **`ChannelOps(Transport)`** — `name = "telegram"`. Its tier-named methods are
  unchanged and still serve all 12 existing call sites.
- **`TransportFan(Transport)`** — fans to N transports, **counts
  attempted/delivered/failed per platform**, logs every non-delivery, contains
  exceptions. Mirrors the tier-named API so it is a true drop-in.
- **`XTransport(Transport)`** — X API v2, OAuth 1.0a HMAC-SHA1 signed with the
  **standard library** (verified against the RFC 5849 reference vector — no
  tweepy/requests-oauthlib dependency). Opt-in via `x_enabled`, off by default.
- **`CardFormatter.to_plain()` / `.fit()`** — strips Telegram HTML and
  box-drawing rules at the two format entry points rather than forking 34 tag
  sites. Real cards: **310–312 chars → 151–153**, inside X's 280 limit.

**Verified no behavior change.** A golden-output harness rendered all 40 event
types through the router and both formatters; pre- and post-refactor digests
are identical (`093bd7d1…`).

> **Harness caveat, if you build another one:** cards embed a live wall-clock
> timestamp ("Fleet Pulse HH:MM UTC · 05 Aug 2026"). A digest over card output
> changes every minute regardless of code. Normalize it — and note that
> normalizing `HH:MM` but not the date passes today and fails at midnight.

## 4. Decisions — RULED 2026-08-05, all four executed

The architect ruled on these after the first draft of this document. Recorded
as decisions with reasoning, not open questions.

**1. §7.2 of the audit was DELETED, not annotated.** A wrong finding whose
remediation is destructive, still readable in isolation, with the correction
elsewhere in the same file. An inline correction only works if you read the
whole document — the same failure as a check that runs at filing time rather
than claim time. The section body is replaced by the correction and the units
explanation; the headline entry and recommendation #1 that also named the
reservation IDs were struck too. **Wrong findings with destructive
remediations don't get to stay legible.**

**2. The TEMPORARY marker and the lock text were retired together.**
`x_post_paid` is true, trades are free, `delay_free_s=0` — so the first thing
the X account would publish read "🔒 Full details for subscribers": a paywall
teaser for a tier that doesn't exist, on an account whose premise is that the
numbers are checkable. Free means free. Free trade cards now publish pair,
result, P/L, **entry, exit, and bot**.

*Found while doing this:* the paid card's `Bot` field had been rendering an
em-dash all along. The emitting bot lives on the event's top-level `source`,
but formatters receive only `data`. Both `format_free` and `format_paid` now
carry `source` through. Pre-existing bug, surfaced only because the field
became public.

**3. trekbot excluded via the registry, not a skip-list.** §2.1 established one
answer to fleet membership — `bot_registry_list()`. Expectancy used a different
notion (whatever had trade history) and still counted a bot retired to
standalone GoldenEye. A skip-list would have made three answers. Both the
per-bot loop and the fleet aggregate now filter through the registry, so the
next retirement drops out automatically. Exclusions are named in the payload
(`excluded_non_members`) rather than silently applied.

**The corrected numbers are materially worse:** 18 trades → **12**, win rate
22.2% → **8.3%**, fleet expectancy −$25.80 → **−$35.42/trade**. trekbot's 6
trades were flattering the average.

**4. The units error got a guard, not a doc.** `CommandCenter/portfolio_math.py`
provides `notional_usd(bot_id, position)`, which knows each bot's semantics
(TurtleSue `total_size` = coins; everyone else `size_usd` = USD) and **raises**
on an unregistered bot rather than assuming USD. Never read a size field
directly. Third coins-vs-dollars incident on this project; documentation is a
rule you must remember when you are least likely to.

**Golden-harness hardening (same session).** Normalizing the timestamp made the
check blind to the bug class that keeps recurring — a format, label, or offset
change would produce an identical digest. It now **asserts the shape, then
blanks the value**, anchored on the digits rather than the "Fleet Pulse" label
so renaming the label cannot silently disable the check. Verified to fire on
offset change, label rename, format change, and dropped date.

## 4c. The 08:00Z daily summary — registered as deltas, not absolutes

Registered before the fire so the result cannot be rationalized after it.

**Why absolutes are the wrong instrument.** `failed_today` resets at UTC
midnight and the summary fires at **08:00Z — eight hours into that day**.
Every whitelisted event type still routes `paid=True` (including TRADE_* which
now also route free), and ~22,000 paid-routable events land on the bus in a
typical 00:00–08:00Z window. So by the fire, `failed_today` is already well
above zero and the once-per-day `PAID CHANNEL UNSET` warning has long since
been consumed by the first paid attempt of the day.

An earlier draft of these predictions said *"failed_today = 1; 0 means the fix
didn't take"* and *"a second warning means the flag isn't holding."* Both would
have misread the fire: the counter will not be 1, and there will be **zero**
warnings at 08:00 — which is correct behavior the list did not cover.

**Registered:**

| # | Prediction | Falsified by |
|---|---|---|
| 1 | `failed_today` increases by **exactly 1** across the fire | any other delta |
| 2 | `free_sent_today` increases by **exactly 1** | 0 = free leg broke |
| 3 | `signals_sent.log` gains **one** paid-failure entry stamped ~08:00Z | missing = log path regressed |
| 4 | `PAID CHANNEL UNSET` warnings for the whole UTC day: **exactly 1**, at any hour | 0 = flag never armed; 2+ = flag not holding |
| 5 | paid *success* | channel resolved after all — §6 needs revisiting |

Measure with `snapshot_0800.py before` at 07:59Z and `after` at 08:01Z; it
prints deltas and checks them against the table. A counter read without its
window is the same defect as a timestamp without its frame — the number is
right, the frame around it was never stated.

**Restart caveat:** the warning is once-per-*day*, re-armed by
`_reset_if_new_day()`. A broadcaster restart between now and 08:00 also clears
the process-local flag, so a second warning would then be correct rather than a
fault. Nothing is scheduled to restart.

## 7. Two process notes worth carrying forward

**A silent failure path produces no evidence of itself.** §2.3 was invisible to
every check that asks "where did this number come from" or "is this number
right," because there was no number and no claim — only an absence. The
instrument that finds it is conservation: count what was attempted, count what
was delivered, compare. That is now built into `TransportFan` per platform,
which matters because every added platform multiplies that surface.

**A declared capability with no live path is equally invisible.** `TRADE_OPEN`
sat in the free-formatter map, correct and unused, because routing never sent
trades to free. Related and nastier: `TransportFan` initially shipped only the
neutral `send_text`/`send_image` while all 12 call sites use the tier-named API
— it would have raised `AttributeError` on the first send the moment a second
transport went live, and no behavioral test could have caught it, because
nothing exercises the fan while one transport is active. The check is
reachability: diff a facade's public surface against the surface its call sites
actually use, before deploying.

**But reachability crosses languages and file types, and this note as first
written did not say so.** Applied literally it gives the wrong answer. Case in
point, same session: `ChannelOps.failed_today` looked dormant — grepping
`stats()` callers in `signal_broadcaster.py` found exactly one consumer, the
`/stats` endpoint, with nothing in any `.py` polling it. Follow the note as
written and you conclude *dormant*, delete the counter, and destroy a live
KPI: `command_center_v4.html:12402` already renders `FAILED` in red when
non-zero, with live-vs-derived provenance tracking. The consumer was HTML and
JavaScript.

So: **a single-language grep answers a different question than "is this
reachable."** Before calling anything dormant, search the consumers' languages
too — templates, dashboards, shell scripts, config, cron. The cost asymmetry
is severe: a missed dormant capability is clutter, a wrongly-deleted live one
is a removed instrument, and the second failure is invisible until the moment
you need the reading.
