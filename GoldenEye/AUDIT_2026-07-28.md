## P0 — CRITICAL (live-money / secrets)

### 1. No serialization of private Kraken API calls (nonce races)
- `_kraken_api_lock` absent. Unlocked private call sites: fetch_balance :450, :5127, :5145; fetch_order :839, :849, :3953, :4025; create_order :866, :882, :4826, :4831, :5002; cancel_order :3974, :4046, :4988, :5119; market orders :4783/:4788, :5135/:5137/:5150/:5152.
- Callers: 20 stream threads + 20 order monitors + reconciler + balance loop + health snapshot.
- Worst case: entry market order fills, concurrent monitor call causes `EAPI:Invalid nonce` on the SL create → **live position with no stop** until RECON (5 min).
- Fix: module-level RLock wrapping every private call — ideally a locking proxy around the exchange object so no call site can be missed. Shared `requests.Session` (:6406) is a second corruption vector.

### 2. Kill switch — implement or delete from docs
- No code. Closest: `get_drawdown_mult()` :421 returns 0 at ≥15% dd, but `_LIVE_PEAK` isn't persisted (:33, :459) so any restart resets drawdown to 0% and full-size trading resumes.

### 3. Circuit breaker: not persisted, can trip forever, wiped by restart
- :362-414, :4246-4249. Rollover/untrip only evaluated inside `update_circuit_breaker()` which only runs on trade close → tripped with no open positions = **tripped forever until restart**; restart = accumulators zeroed. Sliding 86400s windows, no calendar/timezone handling.
- Fix: persist atomically on every update, load at boot, evaluate rollover in the periodic reconciler.

### 4. Market-order retry can double-buy on timeout
- `submit_order_with_retry` :1385-1412 retries `ccxt.NetworkError` (includes `RequestTimeout` — order may have been accepted) up to 3×. Extra fills untracked (exit reconcile only shrinks size, :5127).
- Fix: on RequestTimeout, query open orders/recent trades (or client order id) before retrying; auto-retry only RateLimitExceeded.

### 5. HMM regime detector has NEVER fit in live — everything is 'bull', forever
- `_MIN_BARS = 200` (:1901) but live fetches max 100 bars (:4122, :4158). Fit bails → uniform probs → `argmax` → `_REGIMES[0]` = `'bull'` for every symbol always (:1570).
- **This explains global brain bull regime_n=19, bear/range/chop=0.** All trades get bull's loosest conf floor (0.40) and widest TPs; all learning funnels into one bucket; regime sanity grades a detector that never ran.
- Second bug stacked on top: `startprob_` never assigned (:2010-2025, `init_params='mc'` but only transmat provided) → even with 200+ bars, hmmlearn raises inside fit and the bare except at :2030 swallows it at DEBUG.
- Fix both together: fetch ≥200 (ideally 720) bars for fitting + set `model.startprob_ = np.full(4, 0.25)` + log fit failures at WARNING. Also: refit cadence unit bug — `hd.tick()` counts 4h regime refreshes, not bars, so `_REFIT_INTERVAL=500` ≈ 83 days (:4164, :1903).

### 6. subscribers.json leaks the resolved bot token to disk
- `_load_subscribers` :3665-3672 resolves `${TELEGRAM_BOT_TOKEN}` in place; `_save_subscribers` :3678-3680 dumps that dict — any register/remove/preferences call (incl. HTTP POST on port 18096) writes the **plaintext token into a git-tracked file**, non-atomically, with no lock. Corrupt file → `except: _subscribers = {}` silently (:3673) → next save persists empty set = all subscribers wiped silently.
- Fix: keep pristine raw config for saving, resolve tokens only at send time, atomic write + lock, log the parse error.

### 7. Secrets hygiene
- `C:\Users\Miner\Desktop\launch.bat` holds live Kraken key/secret + Telegram token in plaintext. Rotate if ever shared/synced; move to env vars or a non-synced .env.
